# 2차 체크리스트 — 프론트엔드 (TypeScript / React / Next.js)

해당하는 항목만 쓴다. 포매터·ESLint가 잡는 것은 제외한다.

## 타입

- `any`를 쓴 자리에 실제로 좁힐 수 있는 타입이 있는가
- 타입 단언(`as`)으로 검증을 건너뛰었는가. 외부 응답이면 런타임 검증이 필요하다
- 옵셔널 체이닝(`?.`)이 실제 `undefined` 가능성을 가리는 데 쓰였는가
- 함수 반환 타입을 명시했는가 (public API·훅에서 특히)
- 유니온 분기가 `switch`로 모두 처리됐는가 (`never` 체크)

## 훅

- `useEffect` 의존성 배열이 실제 참조와 맞는가. 빠뜨린 값이 stale closure를 만드는가
- `useEffect`가 정리 함수를 반환하는가 (구독·타이머·`AbortController`)
- 비동기 `useEffect`에서 언마운트 후 `setState`가 호출될 수 있는가
- 파생 가능한 값을 별도 `state`로 들고 동기화하고 있는가 (렌더 중 계산으로 충분한 경우)
- `useMemo`/`useCallback`이 실제로 필요한 자리인가. 원시값 계산에 붙였다면 오히려 손해다
- 커스텀 훅이 조건문·반복문 안에서 호출되지 않는가

## 렌더링

- 리스트 `key`가 인덱스인가. 순서가 바뀌거나 중간 삽입이 있으면 상태가 어긋난다
- 렌더 함수 안에서 객체·배열·함수를 새로 만들어 자식 props로 넘기는가
- 조건부 렌더에 `&&`를 쓰면서 좌변이 `0`이 될 수 있는가 (`0`이 그대로 그려진다)
- 큰 리스트에 가상화 없이 전체를 그리는가

## 데이터 페칭

- 로딩·에러·빈 상태가 모두 처리됐는가
- 요청 취소·race condition 처리가 있는가 (빠른 연속 요청에서 오래된 응답이 나중에 도착)
- 폴링 간격이 하드코딩됐는가. 상수로 뺄 자리인가
- 서버 상태를 클라이언트 전역 상태에 복사해 두고 있는가
- 캐시 무효화 시점이 명확한가

## Next.js App Router

- `'use client'`가 필요한 최소 경계에 붙었는가. 페이지 최상단에 붙여 트리 전체를 클라이언트로 끌어내리지 않았는가
- 서버 컴포넌트에서 브라우저 API(`window`, `localStorage`)를 참조하는가
- 클라이언트 전용 무거운 모듈을 동적 import + `ssr: false`로 격리했는가
- `NEXT_PUBLIC_` 접두사 없는 환경변수를 클라이언트 코드에서 읽는가
- 반대로, 서버 전용 시크릿에 `NEXT_PUBLIC_`이 붙어 번들에 노출되는가
- 이미지에 `next/image`를 쓰는가. `width`/`height` 또는 `fill`이 지정됐는가

## 접근성

- 클릭 핸들러가 `div`에 붙었는가. `button`이면 키보드·포커스가 공짜로 따라온다
- 아이콘 전용 버튼에 접근 가능한 이름이 있는가 (`aria-label`)
- `img`에 `alt`이 있는가. 장식용이면 `alt=""`인가
- 폼 입력에 연결된 `label`이 있는가
- 포커스 표시를 지우고 대체 스타일을 주지 않았는가

## 스타일

- 하드코딩된 색상값이 디자인 토큰·테마 변수를 우회하는가
- 매직 넘버 여백이 스페이싱 스케일을 벗어나는가
- 다크 모드가 있는 프로젝트인데 새 색상이 한쪽 테마에만 정의됐는가

## 성능

- 번들에 큰 라이브러리를 페이지 전역으로 import했는가 (필요한 함수만 가져올 수 있는가)
- `useEffect` 안에서 매 렌더마다 새 구독을 만드는가
- 무거운 계산이 렌더 경로에 있는가
