# 2차 체크리스트 — 공통

언어와 무관하게 보는 것들. 위에서부터 훑되, **해당하는 항목만** 리포트에 쓴다.

## 이 변경이 무엇을 깨뜨리는가

- 함수 시그니처·반환 타입이 바뀌었는데 호출부를 전부 고쳤는가 (Grep으로 확인)
- API 응답 스키마가 바뀌었는데 반대편(프론트/백엔드, 목 데이터)에 반영됐는가
- 삭제한 함수·상수를 아직 참조하는 곳이 있는가
- 설정 파일에 항목을 추가했으면 `.example` 템플릿에도 넣었는가

## 경계 조건

- 빈 배열·빈 문자열·`null`/`undefined`/`0`이 들어오면 어떻게 되는가
- 배열 인덱스 접근 앞에 길이 검사가 있는가
- 나눗셈의 분모가 0이 될 수 있는가
- 첫 렌더·초기 상태에서 데이터가 아직 없을 때의 경로가 있는가
- 응답이 실패했을 때의 분기가 있는가. `catch`가 비어 있지 않은가

## 자원 정리

- 타이머(`setInterval`/`setTimeout`)를 해제하는가
- 이벤트 리스너·구독을 해제하는가
- 스트림·커넥션·파일 핸들을 닫는가
- 오류 경로에서도 정리가 실행되는가 (`finally`, `try-with-resources`)

## 중복

- 방금 만든 유틸이 이미 프로젝트에 있는가 (있을 법한 이름으로 Grep)
- 같은 로직이 세 곳 이상 복사됐는가
- 표준 라이브러리·이미 쓰는 라이브러리로 대체 가능한 직접 구현인가

## 오류 처리

- 삼킨 예외가 있는가 (빈 `catch`, 로그만 찍고 계속 진행)
- 오류 메시지가 원인을 특정하는가 ("에러 발생"은 아무것도 알려주지 않는다)
- 사용자에게 보이는 메시지에 스택 트레이스·내부 경로가 새지 않는가

## 보안

- 하드코딩된 키·토큰·비밀번호·접속 문자열
- 로그에 개인정보·토큰이 찍히는가
- 외부 입력이 검증 없이 쿼리·경로·명령에 들어가는가
- 인가 검사가 필요한 경로인데 인증만 하고 소유권을 확인하지 않는가

## 테스트

- 새로 생긴 분기에 테스트가 있는가
- 버그 수정이면 그 버그를 재현하는 테스트가 있는가
- 테스트가 구현 세부가 아니라 동작을 검증하는가

## 커밋 단위

- 한 커밋에 기능 추가와 리팩토링이 섞였는가
- 의도치 않은 파일이 포함됐는가 (로그, 임시 파일, IDE 설정, 시크릿)
- `UNTRACKED` 목록에 있어야 할 새 소스 파일이 add 누락으로 빠졌는가

## 남은 흔적

- `console.log`·`System.out.println`·`print` 디버그 출력
- `TODO`·`FIXME`에 담당자나 이슈 번호가 없는 것
- 주석 처리된 코드 블록
- 사용하지 않는 import·변수·파라미터 (린터가 안 잡는 경우만)
