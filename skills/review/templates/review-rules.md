## 필수 규칙

<!-- 위반 시 [필수]로 보고됩니다. 머지 전에 반드시 고쳐야 하는 것만 넣습니다. -->

### 금지 문법

- (예) `any` 사용 금지. 불가피하면 `unknown` + 타입 가드로 좁힙니다.
- (예) 2단계 이상 상대경로(`../../`) 금지. 절대경로 `@/`를 사용합니다.
- (예) JPA 엔티티를 컨트롤러 요청·응답에 직접 노출 금지. DTO로 변환합니다.

### 구조

- (예) 컨트롤러에 비즈니스 로직 금지. 로직은 서비스, DB 접근은 리포지토리.
- (예) `'use client'`는 필요한 최소 경계에만 붙입니다.

### 보안

- (예) 비밀번호는 `BCryptPasswordEncoder`로 해시합니다. 평문 저장 금지.
- (예) 시크릿 파일(`.env`, `application-local.yml`)은 커밋하지 않습니다.

## 권장 규칙

<!-- 위반 시 [권장]으로 보고됩니다. 동작에는 지장 없지만 팀이 맞추기로 한 것들. -->

### 네이밍

- (예) 핸들러 함수는 `handle*`, 컴포넌트 prop 콜백은 `on*`.
- (예) 컴포넌트 파일명은 컴포넌트명(PascalCase)과 일치시킵니다.

### 커밋

- (예) Conventional Commits 형식 `<type>(<scope>): <subject>`.
- (예) subject는 50자 이내, 명령문, 마침표 없음.
- (예) body에 무엇을 왜 바꿨는지 적습니다.
- (예) 한 커밋에는 하나의 논리적 변경만 담습니다.

### 브랜치

- (예) `feature/`·`fix/`·`hotfix/`·`chore/` 접두사 + kebab-case.
- (예) 이슈 번호가 있으면 포함합니다 (`fix/12-sse-connection-leak`).
- (예) `main`/`dev` 직접 커밋 금지.

### PR

- (예) 제목은 커밋과 같은 `type: subject` 형식.
- (예) 관련 이슈를 `Closes #번호`로 명시합니다.
- (예) 하나의 PR은 하나의 목적만 다룹니다.

## 이 프로젝트에서 특히 주의할 것

<!--
  일반 체크리스트에는 없지만 이 프로젝트에서 반복해 사고가 났던 지점을 적습니다.
  리뷰의 실질적인 가치가 대부분 여기서 나옵니다.
-->

- (예) 폴링과 SSE는 동일한 스냅샷 스키마를 반환해야 합니다. 전송 방식이 프론트로 새면 안 됩니다.
- (예) 로그인 세션 관련 변수는 `session` 단독 대신 `authSession`으로 짓습니다. 도메인 `Session` 엔티티와 이름이 겹칩니다.
- (예) API 계약을 바꿀 때는 프론트·백엔드 두 레포에 모두 반영합니다.
